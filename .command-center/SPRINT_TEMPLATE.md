# Título

`Sprint NNN`

## Objetivo

Padronizar como um ciclo de entrega é planejado e fechado, dando ao campo `Sprint` (usado em `BACKLOG.md`, `TASK_TEMPLATE.md`) um documento correspondente. Hoje não existe calendário de sprints nem velocidade de equipe registrada em nenhum documento — este é apenas o formato que um sprint usará quando existir.

## Estrutura

```markdown
# Sprint NNN

## Período
## Objetivo do Sprint
## Itens Incluídos (Epics/Features/Stories/Tasks)
## Capacidade da Equipe
## Critério de Sucesso do Sprint
## Riscos Conhecidos
## Retrospectiva (preenchida ao final)
```

## Campos Obrigatórios

| Campo | Descrição |
|---|---|
| Número do Sprint | Identificador sequencial |
| Período | Data de início e fim |
| Objetivo do Sprint | O que este ciclo deve entregar |
| Itens Incluídos | Lista de Tasks/Stories puxadas do backlog para este sprint |
| Capacidade | Quanto a equipe pode entregar no período (**TODO** enquanto não houver dado de velocidade real) |
| Critério de Sucesso | Como saber se o sprint foi bem-sucedido |
| Retrospectiva | O que funcionou, o que não funcionou, ações para o próximo sprint |

## Checklist

- [ ] Todo item incluído já existe em `BACKLOG.md` com Critério de Aceite definido
- [ ] Capacidade da equipe não é presumida sem dado real
- [ ] Objetivo do sprint é verificável ao final do período
- [ ] Retrospectiva é preenchida antes de abrir o próximo sprint
