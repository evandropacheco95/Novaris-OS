# Pilar 9 — Checklists

## Objetivo

Reunir os critérios de verificação obrigatória antes de considerar um trabalho concluído.

## Responsabilidades

Apontar para os checklists já existentes.

## Regras

- Checklist de qualidade geral: [.command-center/ENGINEERING_CHECKLIST.md](../../.command-center/ENGINEERING_CHECKLIST.md).
- Checklist de release: [.command-center/RELEASE_CHECKLIST.md](../../.command-center/RELEASE_CHECKLIST.md).
- Checklist de Pull Request e Definition of Done específicos de serviço: [ENGINEERING_PLAYBOOK.md § 18-19](../../knowledge/engineering/ENGINEERING_PLAYBOOK.md#18-pull-request-checklist).
- Árvore de decisão obrigatória antes de qualquer implementação: [engineering/decision-tree.md](../../engineering/decision-tree.md).
- **Architecture Compliance Report (ACR)** — [.command-center/ARCHITECTURE_COMPLIANCE_REPORT_TEMPLATE.md](../../.command-center/ARCHITECTURE_COMPLIANCE_REPORT_TEMPLATE.md): obrigatório junto com o Self Review para toda missão ser considerada concluída, desde a Ordem de Missão ENG-0002.A ("Architecture Governance Update", CTO, MANDATORY). Passa a fazer parte oficial deste pilar do NEF.

## Exemplos

Antes de considerar o Identity Service pronto, os checklists acima se aplicam em conjunto: `decision-tree.md` antes de começar, `ENGINEERING_PLAYBOOK.md § 18` no PR, `RELEASE_CHECKLIST.md` antes do deploy, Self Review + ACR ao encerrar cada missão.
